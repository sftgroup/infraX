# 需求文档 5：自动寻找因子（对话驱动 + 偏好限制）

> 需求方：Steven ｜ 归档：**InfraX（独立）** ｜ 日期：2026-08-09 ｜ 状态：待开发
> 定位：**细化的「自动寻找因子」功能**。核心两点：
> ① **可写偏好、设定限制** —— 因子挖掘的方向偏好（市场/风格/价值）、约束条件（资源/耗时/范围）、阈值门槛
> ② **通过 AI 对话启动 + 查看状态** —— 用自然语言对话（LLM + MCP）下发任务、设定偏好/限制、启动挖掘、追踪进度、查看结果
> 承接既有设计：〔InfraX 找银根因子设计〕的 L0–L6 因子体系 + `factor_pool` / `factor_eval` + `FACTOR_AUTO_CONF`。

---

## 1. 背景与目标

现有 InfraX ml-service 的因子是**硬编码 14 因子**（`tree_models.build_features`），找因子方案已规划 L0–L6 全因子体系 + 自动挖掘管线（factor_pool → factor_eval → 入库/top-K/IC淘汰），但：
- **没有「偏好 / 限制」输入层**：用户/LLM 无法指定挖什么方向、预算多少、门槛多高
- **没有对话接口**：只能手工改配置触发，不能"说一句话"就启动并追踪

**目标**：新增**对话驱动的自动因子挖掘**，LLM（或用户直接对话）可：
- 用自然语言设定**偏好**（传统/链上、技术/基本面/宏观/资金、价值/动量）
- 用自然语言设定**限制**（市场范围、标的池、计算预算、耗时上限、因子数量上限）
- **启动**挖掘任务 → **查看进度/状态** → **查看结果**（入选因子、IC、稳定性）

---

## 2. 核心交互模式（AI 对话）

```plaintext
用户/LLM 一句话：
  "挖一些美股的技术面动量因子，20个以内，跑不超过5分钟"
  "帮我看看链上资金流有趋势的因子，限制在以太坊生态"
  "我要价值银子因子，财报+宏观，最多30个因子，用CPU跑"

        │ 自然语言
┌───────▼────────────────────────────────────────────┐
│  Factor-Factory（对话层，独立或并入 ml-service）      │
│  ① 意图解析：识别 偏好 + 限制                      │
│  ② 生成"挖掘任务配置"(job spec)                    │
│  ③ 下发 factor_pool/factor_eval 执行                │
│  ④ 返回状态/进度/结果                               │
└───────┬────────────────────────────────────────────┘
        │ 结构化 job spec
┌───────▼────────────────────────────────────────────┐
│  InfraX ml-service 因子挖掘内核                      │
│  factor_pool → factor_eval → 选因/淘汰 → 入库        │
└────────────────────────────────────────────────────┘
```

**关键**：偏好/限制先转成**结构化 job spec**（JSON），再交给挖掘内核，而不是把自然语言直接塞进计算管线。这样可复现、可追踪、可审计。

---

## 3. 偏好与限制（细化）

### 3.1 偏好（direction / preference）

| 偏好维度 | 选项 | 说明 |
|---------|------|------|
| **市场类型** | 传统 / 链上(DEX) / 混合 | 传统=财报+宏观+技术；链上=资金+叙事+链上活跃 |
| **因子风格** | 技术面 / 基本面 / 宏观 / 资金流 / 叙事 / 混合 | 对应 L1-L6 |
| **投资风格** | 价值银子 / 动量银子 / 趋势银子 | 影响标签(超额/反转)与选因偏好 |
| **资产池** | 美股/加密/ETF/指定列表 | 缩小标的范围 |
| **周期偏好** | 短(分钟/小时)/中(日)/长(周/月) | 影响因子窗口 |

### 3.2 限制（constraints / guardrails）

| 限制 | 示例 | 说明 |
|------|------|------|
| **因子数量上限** | ≤ 30 个 | 控制结果规模 |
| **计算资源预算** | CPU 或 GPU、最多 N 核 | 防止吃满机器 |
| **耗时上限** | ≤ 5 分钟 / 30 分钟 | 超时自动停止或减量 |
| **标的数量上限** | ≤ 100 | 控制样本量 |
| **IC 门槛** | |IC| | 因子有效性 |
| **稳定性门槛** | ICIR ≥ 0.3 | 防止单时段偶然 |
| **单调性要求** | 分位单调 | 可选 |
| **与现有因子独立度** | |corr| | 去冗余 |
| **市场范围黑/白名单** | 排除某类st/退市 | 合规/风控 |

### 3.3 偏好/限制的默认值与安全

- 未指定时用**保守默认**（少量因子、CPU、限时、低门槛从严）
- **硬限制不可被偏好覆盖**（如计算预算、标的池白名单）
- 冲突时提示用户/LLM 确认

## 4. 对话接口（LLM / MCP tools）

| 操作 | tool / 端点 | 说明 |
|------|------------|------|
| 启动挖掘 | `factor_factory.start(spec)` | 传偏好+限制，返回 job_id |
| 状态查询 | `factor_factory.status(job_id)` | 进度/阶段/耗时 |
| 结果查看 | `factor_factory.result(job_id)` | 入选因子、IC、稳定性报告 |
| 任务列表 | `factor_factory.list()` | 历史任务 |
| 取消 | `factor_factory.cancel(job_id)` | 停止并保留部分结果 |

**意图解析**：MCP 工具接收结构化参数（preferences + constraints），LLM 负责把自然语言转成这两个 JSON 结构。挖掘内核不吃自然语言。

---

## 5. 挖掘任务状态机

```plaintext
CREATED → PARSED(意图/偏好/限制已解析)
        → QUEUED → RUNNING(POOL→EVAL→SELECT→PERSIST)
        → COMPLETED(返回报告) / FAILED / CANCELLED / TIMEOUT
```

- **持久化**：job 存 DB（`factor_jobs` + `factor_results`），重启可恢复
- **状态可续**：LLM 多轮对话中可 `factor_factory.status(job_id)` 拿回进度
- **部分结果保留**：超时/取消时已算完的因子结果不丢

---

## 6. 挖掘内核（复用既有设计）

- `factor_pool.py`：从 L0–L6 因子模板 + 参数展开（100+）→ 按偏好过滤
- `factor_eval.py`：IC / 超额 / 单调性 / 独立度评估（用超额/回报倍数标签）
- **选因**：top-K + 去冗余（独立度）+ IC 淘汰
- **入库**：合格因子写 `factors_catalog.json` 或 DB，后续供 alpha_scoring 使用
- 配置：`FACTOR_AUTO_CONF=none|evaluate|auto`（沿用）

---

## 7. 技术栈

- InfraX ml-service（复用）或独立 Factor-Factory 微服务（待定）
- 意图解析：LLM（DeepSeek API / 本地 V100 LLM）
- MCP：暴露 factor_factory 工具集
- DB：PostgreSQL（job + result）
- 硬件：CPU 挖掘默认；偏好可指定 GPU（V100 32G，加速大因子池评估）

## 8. 里程碑

| 阶段 | 内容 |
|------|------|
| M1 | 偏好/限制结构化(job spec) + factor_pool/factor_eval 内核(可配置) |
| M2 | 任务状态机 + 持久化 + 异步执行 |
| M3 | MCP 对话工具集(start/status/result/list/cancel) |
| M4 | LLM 自然语言→spec 意图解析 + 结果报告/可视化 |

---

## 9. 验收标准

- [ ] 可用自然语言设定偏好+限制并启动挖掘，无需改配置/代码
- [ ] 硬限制始终生效，偏好不越界（预算/数量/耗时被控制）
- [ ] 任务状态可随时查询，多轮对话可恢复
- [ ] 产出因子报告：入选因子、IC、ICIR、独立度、稳定性
- [ ] 冲突的偏好/限制有提示，不静默

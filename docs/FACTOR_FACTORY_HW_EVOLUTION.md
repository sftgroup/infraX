# 因子工厂硬件进化方案（双路 E5-2683v4 + 64G 内存 + V100 32G）

> 需求方：Steven ｜ 日期：2026-08-09 ｜ 状态：方案

> 评估预设服务器：**双路 Xeon E5-2683v4 + 64G 内存**，显卡分两阶段：**单路 V100 32G** → **双卡 V100 32G**。本文评估：在此硬件下，**因子工厂（InfraX ml-service 因子引擎）如何分阶段进化**。

## 0. 硬件基准

| 项 | 值 | 关键词 |
|------|------|------|
| CPU | 2× E5-2683v4 = **32核/64线程**（Broadwell 2016） | 多核强、单核弱 |
| 内存 | **64G DDR4**（8通道 ECC） | 大、带宽高 |
| GPU(阶段1) | **1× V100 32G** | 16G显存单卡 |
| GPU(完整) | **2× V100 32G** = 64G | 双卡并行 |
| note | V100(Volta) 不支持 bf16，仅 fp16 | 框架强制 fp16 |

相对此前 3600X+32G 方案：**多核 + 内存大幅提升，显存按阶段扩展**。

## 1. 因子工厂的计算画像（哪些吃硬件）

| 因子工厂环节 | 计算类型 | 吃CPU多核 | 吃内存 | 吃GPU |
|------|------|:--:|:--:|:--:|
| 因子计算（L0-L6 全标的×全因子） | 数值矩阵 | ✅高 | ✅中 | 低 |
| 因子评估（IC/ICIR/单调性/独立度） | 统计+相关矩阵 | ✅高 | ✅高(全样本) | 低 |
| 选因/去冗余（top-K/去重） | 优化 | 中 | 中 | 低 |
| LLM 语义增强（财报/电话会→因子） | 推理 | 低 | 中 | **✅高** |
| 因子相关挖掘（GNN/非线性交互） | 图/深度 | 中 | ✅高 | **✅高** |
| 大批量回测联动（供策略工厂） | 计算 | ✅高 | 中 | 低 |

**结论**：因子工厂主体（因子计算/评估）是 **CPU多核 + 内存** 主导；GPU 主要在 **LLM 语义因子 和 因子间关联挖掘(GNN)** 加速。

## 2. 阶段一：双路 2683v4 + 64G + 单路 V100 32G

> 覆盖绝大多数需求：因子计算、评估、选因、LLM 因子增强。

### 能力进化
| 能力 | 3600X+32G 旧 | **本阶段(单V100)** |
|------|------|------|
| 全标的×全因子矩阵计算 | ⚠️ 慢 | ✅ **32核并行快数倍** |
| 因子评估(IC矩阵/独立度) | ⚠️ 受限 | ✅ **64G 内存装全样本** |
| LLM 语义因子(13B 本地) | ✅ 32G 紧张 | ✅ **64G offload 更宽裕** |
| 多模型并发推理 | ⚠️ 6核吃紧 | ✅ **32核并行喂** |
| L0-L6 全因子挖掘 | ⚠️ 慢 | ✅ **常规周期可跑完** |

### 对因子工厂的意义
- **① 挖掘规模化**：双路 32 核 + 64G 内存 → 因子池（100+ 模板展开）全量评估可行，IC/ICIR 矩阵计算不再卡内存
- **② LLM 因子落地**：V100 32G 跑 7B/13B 本地 LLM 做财报/电话会 → `guidance_bias`、`rug` 审查（全程离线，隐私好）
- **③ 入库打通**：合格因子入库 data-service `/factors/current`，供策略工厂消费（本阶段即可全链路跑通）
- **④ 对话挖掘**：偏好+限制(需求5)的挖掘任务，本阶段可承担常规规模

### 局限（本阶段）
- 单卡 32G：**超大模型（>30B）张量并行放不下**，本地 LLM 上限约 13B-26B(量化)
- 因子间**非线性关联挖掘(GNN)**受显存限制，规模有限

## 3. 阶段二：双路 2683v4 + 64G + 双卡 V100 32G

> 锦上添花：解锁超大 LLM + GNN 因子关联挖掘 + 多任务并行。

### 能力进化（新增）
| 能力 | 单V100 | **双V100(完整)** |
|------|------|------|
| 超大本地 LLM(33B) | ❌ offload勉强 | ✅ **双卡张量并行** |
| 因子关联挖掘(GNN/AutoML) | ⚠️ 受限 | ✅ **双卡跑图网络** |
| 多任务并行 | ✅ | ✅✅ **一张跑预测、一张跑LLM/GNN** |
| 因子语义增强质量 | 13B | ✅ **33B 读财报/白皮书更准** |
| 批量回测联动 | ✅ | ✅✅ 更高吞吐 |

### 对因子工厂的意义（深化）
- **① 复合因子 / 非线性交互**：双卡可跑 GNN/AutoML 做**因子间关联挖掘**，找出超越单因子的复合信号（这是单卡做不到的跃升）
- **② 更强 LLM 因子**：33B 模型理解复杂财报/电话会/白皮书 → 更精准的 `guidance_bias`、叙事因子、rug 审查
- **③ 双任务并发**：一张卡持续跑 TimesFM-2.5B 预测，一张卡跑 LLM/GNN 因子挖掘，互不干扰
- **④ 更大因子搜索空间**：AutoML 自动特征工程规模可放大

### 本阶段才是"完整态"
- 因子工厂从"挖掘单因子"升级到"挖掘**因子交互/复合因子**"
- 因子质量与数量双提升，策略工厂可消费更丰富因子

## 4. 两阶段能力对照表

| 能力 | 3600X+32G | **2683v4+64G+1×V100** | **2683v4+64G+2×V100** |
|------|:--:|:--:|:--:|
| L0-L6 因子全量挖掘 | ⚠️ | ✅ 快数倍 | ✅✅ |
| 因子 IC/独立度矩阵评估(64G) | ⚠️ | ✅ | ✅ |
| 因子入库 /factors/current | ✅ | ✅ 全链路 | ✅ |
| LLM 语义因子(本地) | ✅13B紧张 | ✅13B-26B | ✅✅33B |
| GNN/AutoML 因子关联挖掘 | ❌ | ⚠️ | ✅✅ |
| 复合因子 / 非线性交互 | ❌ | ⚠️ | ✅ |
| 多任务并行(预测+挖因子) | ❌ | ✅ | ✅✅ |
| 对话驱动挖掘(需求5) | ✅ | ✅ 常规规模 | ✅✅ 大规模 |

## 5. 建议落地路线

| 阶段 | 硬件 | 因子工厂落地 |
|------|------|------|
| **P0** | 现有/单V100 | 需求4 因子解耦 + factor_pool/eval 内核 + 入库打通 |
| **P1** | 单V100 | L0-L6 全因子挖掘 + LLM(13B)语义因子 + 对话驱动(需求5) |
| **P2** | 单V100→双V100 | 扩大因子池规模 + 提升 LLM 到 26B+ |
| **P3** | 双V100(完整) | GNN/AutoML 复合因子挖掘 + 33B LLM + 多任务并行 |

**核心判断**：
- **单 V100 阶段已覆盖因子工厂 90% 需求**：挖掘、评估、LLM 因子、入库、对话全链路可跑通
- **双 V100 是"挖掘上限跃升"**：解锁复合因子/GNN/超大LLM，属优化项而非必需
- CPU(32核) + 内存(64G) 是因子工厂**最基础也最关键的底座**——即使只有单卡，这两项已让挖掘能力远超旧方案

## 6. 硬件注意（延续既有结论）
- V100(Volta) 无 bf16 → 框架强制 fp16；FP16 对量化/时序因子精度足够
- 双路 E5-2683v4（Broadwell）单核较弱：吃单核的少量因子/IO 任务可能偏慢，但 32核+64G 优势远超
- V100 需双 8pin + 服务器散热（≥750W PSU）+ 需一块亮机卡（2683v4 无核显、V100 无视频输出）
- 双卡需确认主板/电源支持双 8pin×2

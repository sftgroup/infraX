# AItrader 侧图谱端点性能问题说明与优化需求（2026-08-20）

> 提交方：AItrader 项目 ｜ 日期：2026-08-20
> 背景：金融图谱全部经 dx_ key 单入口（RK-1~RK-5 已确认）。本单聚焦**图谱端点首次响应慢**问题，附 AItrader 侧已做的本地缓解措施，需 B 端评估服务端优化。
> 状态标记：🔲 待 B 端 ｜ ✅ 已确认 ｜ ⚠️ 异常待修

---

## 1. 问题现象（AItrader 生产实测，2026-08-20）

### 1.1 现象

生产前端（`https://aitrader.0xainet.top`）图谱洞察页首次打开时：

- **首次请求图谱数据 >60s 无响应** → 前端 30s 超时中止请求（浏览器 `net::ERR_ABORTED`）
- 手动 **Refresh 后约 1 分钟数据到达**并正常渲染（说明 B 端在后台完成了生成）
- 首次之后请求明显变快（B 端侧缓存/生成已完成）

涉及端点（均 dx_ key）：

| 端点 | 首次响应（实测） | 缓存后 |
|---|---|---|
| `GET /factors/graph/entities`（力导向图，namespace=market） | >60s（浏览器观测，前端 30s 被中断） | 秒级 |
| `GET /factors/graph/edges`（相关性图边） | 2.5~10s+（偶发 >10s） | <500ms |

### 1.2 影响

- 用户首访图谱页需等待 1 分钟或刷新一次，体验差
- 前端 30s 超时中断请求后，B 端仍在计算（浪费计算资源）
- 移动端弱网/慢速设备更易触发

---

## 2. AItrader 侧已做的缓解（2026-08-20 已上线）

| 措施 | 说明 |
|---|---|
| **data-service 本地缓存** | 图谱端点响应缓存在 data-service（进程内 MemoryCache）：`entities`/`factors` 1h、`edges`/`history` 30m；缓存 key 对 `symbols` 顺序无关（`BTC,ETH` ≡ `ETH,BTC`）；冷缓存首次回源 B 端成功后写入 |
| **超时放宽** | data-service 对 `entities`/`factors` 放宽至 60s、`edges` 30s；analysis-service 90s；前端图 API 90s |
| 实测效果 | `/graph/edges` 回源 0.06s → 本地命中 **0.003s**；`/graph/entities` 0.11s → **0.006s** |

> 本地缓存解决了**二次及以后请求**的延迟，但**首次冷缓存**仍受 B 端生成速度制约（>60s）。这是本单请求 B 端配合的核心。

---

## 3. 需求（需 B 端评估）

### R1 图谱结果服务端缓存（建议优先）

- 首次生成后对**相同查询**（symbol/namespace/limit 组合）缓存结果（Redis 或磁盘），直接返回，不再重复构建
- 实体/文档增量更新时**保持旧图可用**，后台重建新图，构建完成后原子切换（避免更新窗口期 503/慢响应）

### R2 首次生成异步化

- 冷缓存查询返回 `202 Accepted` + `jobId`，B 端后台生成；客户端轮询 `GET .../status?jobId=` 或等 `data updated` 后再取
- 避免请求方长时间占用连接，也避免前端超时中断后 B 端继续空算

### R3 生成链路性能优化（供参考）

- embedding 结果缓存（同一文档/实体不重复向量化）
- 图谱构建分片/增量构建（仅处理新增文档），或对已生成子图复用
- 若生成链路含 LLM 调用，评估并发/批处理

### R4 响应 SLA 建议（公开承诺）

- 缓存命中：P95 < 500ms
- 首次冷生成：P95 < 10s（若 R1/R2 落地后目标）
- 失败返回结构化错误（如 `503 + reason`），便于 AItrader 侧区分「生成中」与「真实故障」，当前 fail-silent 无法区分

---

## 4. AItrader 侧配合

- 本地缓存已能显著降低后续请求延迟；若 B 端 R1 落地，AItrader 侧可将 TTL 调整至与 B 端一致（避免两层过期不一致）
- 若 B 端采用 R2 异步模式，AItrader 侧前端将适配 jobId 轮询流程
